fetch-menus：菜单备份 Skill

痛点

数据同步时可能覆盖其他系统的新增菜单，导致菜单丢失。之前靠后端提醒、前端手动备份，但一个系统有 6 个环境（dev/test/pngs/ungs/stngs/production），一个人维护多个系统，手动备份非常繁琐。

解决方案：开发 fetch-menus skill，一句话即可单个或批量备份各环境菜单，覆盖 20+ 站点系统。

提示词与效果

单个备份

备份核酸制备系统的dev环境菜单，令牌是 xxxxxxxxxxxxxxxx

批量备份

备份蛋白生产、荧光定量V2、核酸制备系统的所有环境菜单

claude-session-monitor

背景

Claude Code CLI 没有消息通知功能，任务完成后无法及时得知。需要一个类似 Workbuddy 的消息通知方案。

定位：给 Claude Code 每次会话请求加上"开始埋点 + 结束判断 + 条件通知"的本地监控工具

生命周期

核心工具与通知效果

工具1：get_last_session_status

查看最近一次会话的监控状态：开始时间、结束时间、耗时和是否已通知。

工具2：test_notification

发送 Windows 右下角测试通知，用于验证通知链路是否可用。

应用场景与局限性

应用场景

  • 长时间任务完成提醒，不用一直盯着终端等结果
  • 会话耗时回溯，评估复杂 prompt 的执行效率

特别适合长编译、批量处理等耗时操作场景

局限性

Windows 通知只会显示 5 秒，系统级别的限制。

自动化测试初探

背景

  • 项目开发完成后测试周期长、频次不固定
  • 开发环境自测通过，推到测试环境后因数据差异导致报错
  • 需要自动化的回归测试保障

PageAgent 探索

阿里的 GUI Agent，基于 Chrome 插件和大模型进行自动化操作。但体验下来效果不顺畅，MCP Server 处于 beta 阶段，不稳定。

PageAgent 的问题

功能单一

只是闷着头测试，不给出汇总结果

无法获取本地文件

不记录上下文

每轮会话都是新的，不记住之前的测试结果

结论：PageAgent 不够成熟，经常莫名报错，无法满足实际需求

传统方式 vs AI + Playwright

传统方式

  • 开发者手动编写 Playwright 脚本
    如 page.click()、expect().toBeVisible()
  • 测试用例以代码形式固化在测试文件中
  • 维护成本高，UI 变化时需改代码

AI + Playwright

  • 自然语言提示词就是测试用例
    如："输入错误密码，然后点击登录按钮，检查是否提示密码错误"
  • AI 自动生成对应的 Playwright 脚本
  • 通过 AI 工具直接驱动 Playwright 运行

AI + Playwright 工作流

解析测试文档 → 执行 Playwright 测试 → 生成测试报告 → 汇总结果反馈

测试文档驱动自动化

测试文档覆盖内容

  • 环境配置（URL/Token/浏览器）
  • 测试范围（菜单模块/子页面）
  • 操作流程（列表/搜索/表单/详情）
  • 判定标准（通过/失败/异常）
  • 异常处理策略（超时/报错/弹窗）
  • 数据清理

当前测试范围

蛋白生产系统测试环境（只读模式）

结合 Superpowers：自动修复不中断

借助第三方 skill、MCP server，最大化提升 Playwright 自动化测试效率。

测试中遇到问题，Superpowers 会自动处理修复，而不是中断任务。修复后继续执行自动化操作，无需人工干预。

Superpowers + Playwright 工作流

发现问题 → 自动修复 → 继续执行 → 完成测试

测试深度

实验人员 - 列表页面

抽提方法 - 编辑页面被打开

混样方案 - 编辑弹窗组件被打开

深度测试能力：AI + Playwright 自动化从列表页延伸至二级表单详情页，能模拟"编辑打开"等复杂交互，验证页面渲染与数据回填的正确性，整个测试过程就像真人在通过浏览器访问系统。

不足：更复杂的业务流转无法覆盖，测试数据较少，无法进行更深入的自动化测试。

对于 AI 自动化编排的思考

🧪

1. 自动化系统测试

AI + Playwright + Superpowers 按测试文档驱动执行，覆盖列表页、表单详情页等完整业务流程，自动截图留档

↓
📊

2. 智能分析测试报告

AI 解析测试报告：Minimax MCP 识别控制台/页面截图中的错误，DeepSeek 分析提取的文本信息，精准定位 Bug 根因

↓
🔧

3. AI 自动修复代码

AI 根据第 2 步的定位信息自动修复问题模块，修复后触发 Playwright 回归测试

↓
👀

4. 人工审核 + 复测确认

修复完成后 claude-session-monitor MCP 会及时通知提醒开发者，人工 Review 代码变更并执行复测，确保 Bug 真实解决

↓
🚀

5. AI 自动提交代码

人工确认后，AI 基于 git-commit-convention Skill 生成 commit message 并推送到远程仓库，闭环交付
